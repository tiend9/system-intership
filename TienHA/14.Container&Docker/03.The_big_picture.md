# The big picture

Chúng ta sẽ xem góc nhìn từ 2 phía:

- Góc nhìn Ops
- Góc nhìn Dev

Trong phần góc nhìn Ops, chúng ta sẽ tải một image, khởi chạy một container mới, đăng nhập vào container đó, chạy một lệnh bên trong nó, và sau đó xóa nó.

Trong phần góc nhìn Dev, chúng ta sẽ tập trung nhiều hơn vào ứng dụng. Chúng ta sẽ clone một đoạn mã ứng dụng từ GitHub, kiểm tra một Dockerfile, đóng gói ứng dụng thành container, và chạy nó như một container.

## I. THE OPS PERSPECTIVE

Khi bạn cài đặt Docker, bạn sẽ có 2 thành phần chính:

- Docker client
- Docker daemon (Docker engine)

Daemon triển khai runtime, API và mọi thứ cần thiết để chạy Docker

### 1. Images

Sẽ hữu ích nếu bạn nghĩ Docker image như một đối tượng chứa filesystem của hệ điều hành (OS), một ứng dụng, và tất cả các phụ thuộc của ứng dụng đó. Nếu bạn làm trong mảng vận hành (Ops), nó giống như một template máy ảo (virtual machine template). Một template máy ảo về cơ bản là một máy ảo đã dừng. Trong thế giới Docker, một image thực chất là một container đã dừng.

### 2. Containers

Ta có thể dùng lệnh `docker container run` để khởi chạy một container từ nó sau khi đã có image

### 3. Attaching to running containers

Bạn có thể gắn (attach) shell của mình vào terminal của một container đang chạy bằng lệnh `docker container exec`.

**Cú pháp:**

```bash
docker container exec <options> <container-name hoặc container-id> <command/app>
```

**Ví dụ:**

```bash
root@labdockersv:~# docker container exec -it distracted_albattani bash
root@ab608aab6eac:/#
```

Trong đó:

- `docker container exec`: Chạy 1 command trong container đang chạy
- `distracted_albattani`: tên container
- `-it`: Cho phép gõ lệnh trực tiếp như đang dùng terminal thật
- `bash`: command được chạy bên trong container

Thoát khỏi container bằng `Ctrl + P + Q` -> bạn sẽ quay lại terminal của Docker host

Kiểm tra lại container trên Docker host:

```bash
root@labdockersv:~# docker container ls
CONTAINER ID   IMAGE           COMMAND           CREATED             STATUS             PORTS                                         NAMES
21d5c257ea41   test:latest     "node ./app.js"   47 minutes ago      Up 46 minutes      0.0.0.0:8080->8080/tcp, [::]:8080->8080/tcp   webtest
ab608aab6eac   ubuntu:latest   "/bin/bash"       About an hour ago   Up About an hour                                                 distracted_albattani
root@labdockersv:~#
```

Dừng và xóa container:

```bash
root@labdockersv:~# docker container stop distracted_albattani
distracted_albattani
root@labdockersv:~# docker container rm distracted_albattani
distracted_albattani
root@labdockersv:~#
```

Kiểm tra lại bằng cách liệt kê tất cả container (kể cả đã dừng):

```bash
root@labdockersv:~# docker container ls -a
CONTAINER ID   IMAGE           COMMAND           CREATED             STATUS                           PORTS                                         NAMES
21d5c257ea41   test:latest     "node ./app.js"   49 minutes ago      Up 49 minutes                    0.0.0.0:8080->8080/tcp, [::]:8080->8080/tcp   webtest
bac83338bba6   ubuntu:latest   "/bin/bash"       About an hour ago   Exited (130) About an hour ago                                                 objective_blackwell
root@labdockersv:~#
```

- `-a`: Docker hiển thị cả container đã dừng

## The DevPerspective

Trước hết, để **hiểu góc nhìn của development về Docker** ta cần biết 1 số khái niệm rất quan trọng đó là:

### **Microservices application** là gì ?

- Là một app có kiến trúc phần mềm trong đó một ứng dụng lớn được chia thành **nhiều dịch vụ (service) nhỏ**, mỗi service đảm nhiệm **một chức năng nghiệp vụ riêng**, chạy độc lập và giao tiếp với nhau qua mạng (thường là HTTP/REST, gRPC hoặc message queue như Kafka, RabbitMQ).

**Ví dụ**:

*Ta xây dựng một website bán hàng.*

Nếu dùng **Microservices** thì sẽ tách ra:

```bash
                API Gateway
                     |
 ------------------------------------------------
 |        |          |          |               |
User   Product    Order     Payment      Notification
Service Service   Service    Service        Service
```

**Mỗi service**:

- Có source code riêng
- Có database riêng (khuyến nghị)
- Deploy riêng
- Scale riêng
- Có thể viết bằng ngôn ngữ khác nhau

**Ví dụ**:

```text
User Service        -> Python (FastAPI)
Product Service     -> Go
Order Service       -> Java Spring Boot
Payment Service     -> Node.js
Notification        -> Rust
```

**Chúng giao tiếp**:

```text
Order Service
      |
      | REST/gRPC
      v
Payment Service
```

Hoặc:

```text
Order Service
      |
      | Kafka Event
      v
Notification Service
```

**Ví dụ thực tế**:

Khi người dùng bấm `Đặt hàng`:

```text
Client
   |
   v
API Gateway
   |
   v
Order Service
```

Order Service sẽ:

```text
1. kiểm tra tồn kho
      |
      v
Inventory Service

2. tạo đơn hàng

3. gọi Payment Service

4. Payment thành công

5. gửi event
Kafka
   |
   +----> Email Service
   |
   +----> SMS Service
   |
   +----> Loyalty Service
```

=> Mỗi service chỉ làm đúng việc của nó.

### **Monolithic application** là gì ?

- **Monolithic application (ứng dụng nguyên khối)** là kiểu kiến trúc phần mềm mà toàn bộ chức năng của ứng dụng được xây dựng và triển khai như một chương trình duy nhất.

**Ví dụ**:

*Bạn cũng xây dựng một website bán hàng.*

Tất cả đều nằm trong cùng một project:

```text
ecommerce/
├── user/
├── product/
├── order/
├── payment/
├── shipping/
├── notification/
├── database/
└── main.py
```

Khi chạy:

```python
python main.py
```

Hoặc:

```java
java -jar ecommerce.jar
```

=> Thì toàn bộ ứng dụng được khởi động.

=> Chỉ cần sửa phần Payment thì phải build và deploy lại cả ứng dụng.

=> Monolithic vẫn là lựa chọn rất tốt khi:

- Dự án mới hoặc MVP (Minimum Viable Product).
- Đội ngũ nhỏ (1–10 developer).
- Nghiệp vụ chưa quá phức tạp.
- Muốn phát triển nhanh và giảm chi phí vận hành.

=> Nhiều sản phẩm nổi tiếng cũng bắt đầu dưới dạng **monolithic** rồi mới tách dần thành **microservices** khi quy mô người dùng và đội ngũ phát triển tăng lên.

### Microservices trong Cloud ?

Hầu hết các nền tảng cloud hiện đại đều xây dựng dịch vụ theo kiến trúc **microservices**:

```text
Amazon Web Services (AWS)
Microsoft Azure
Google Cloud
OpenStack Foundation (nhiều dịch vụ độc lập như Nova, Neutron, Cinder, Glance...)
```

**Ví dụ trong OpenStack**:

```text
Nova        -> Quản lý VM
Neutron     -> Network
Glance      -> Image
Cinder      -> Block Storage
Keystone    -> Identity
Heat        -> Orchestration
Swift       -> Object Storage
```

Mỗi dịch vụ là một service độc lập, có API riêng và thường chạy trong các tiến trình hoặc container riêng, nên có nhiều đặc điểm của kiến trúc **microservices**.

### Virtualization ?

Ảo hóa cho phép một máy vật lý chạy nhiều máy tính ảo độc lập.

### Containerization là gì ?

Container không tạo máy tính mới, mà chỉ tạo môi trường cô lập để chạy ứng dụng.

Các container:

- dùng chung kernel của host
- chỉ có thư viện và ứng dụng riêng (`python 3.11`, `uvicorn`, `requirement.txt`,..)
- nhẹ hơn VM rất nhiều.

### Góc nhìn của Dev đối với Docker là gì?

Từ góc nhìn của developer, **Docker** là công cụ để **đóng gói** (**container hoá**) ứng dụng cùng toàn bộ môi trường chạy của app (cả mono app và micro app)

- Với **Monolith**: thường chỉ cần 1 (hoặc vài) container cho app, đơn giản hơn nhiều.
- Với **microservices**: mỗi service là 1 container riêng, cần thêm công cụ **orchestration** như **Kubernetes** hoặc **Docker Swarm** để quản lý hàng chục/hàng trăm container, **service discovery**, **load balancing**...

### Docker solution for Development ?

Các nhà phát triển khi triển khai app trên Docker thường quan tâm 2 thành phần sau:

- `Dockerfile`
- `Docker Compose`

#### Dockerfile

Developer tạo một `Dockerfile`:

```dockerfile
FROM python:3.12

WORKDIR /app

COPY requirements.txt .

RUN pip install -r requirements.txt

COPY . .

CMD ["uvicorn", "app:app"]
```

Build thành file cài đặt app (Ví dụ: `my-app`)

```bash
docker build -t my-api .
```

Muốn chạy app:

```bash
docker run -p 8000:8000 my-app
```

Lúc này image đã chứa:

- Python 3.12
- FastAPI
- Uvicorn
- mọi package
- source code

=> Bất kỳ ai chạy image này đều có cùng môi trường.

=> Image giống như một "gói cài đặt" hoàn chỉnh của ứng dụng.

=> Khi triển khai **microservices app** thì mỗi service có 1 dockerfile, ta chỉ chạy container từ các image này.

#### Docker Compose

Khi phát triển app , Dev thường cần nhiều thành phần cùng chạy:

- API
- Database
- Redis
- RabbitMQ

Thay vì cài từng phần lên máy, Dev khai báo trong `docker-compose.yml`:

```yaml
services:
  api:
    build: .

  postgres:
    image: postgres:17

  redis:
    image: redis

  rabbitmq:
    image: rabbitmq
```

Chỉ cần:

```bash
docker compose up
```

Là toàn bộ môi trường phát triển được khởi động.

### Benefit of Docker

- Không cần cài nhiều phần mềm trực tiếp trên máy.
- Môi trường của mọi thành viên trong nhóm gần như giống hệt nhau.
- Dễ tái tạo lỗi vì môi trường nhất quán.
- Có thể chạy nhiều phiên bản của cùng một phần mềm (ví dụ `PostgreSQL 15` và `17`) mà không xung đột.
- Dễ tích hợp với CI/CD vì pipeline chỉ cần build và chạy image
