# DOCKER CLI _ CÁC LỆNH THƯỜNG DÙNG

**Docker CLI** giao tiếp với dockerd qua REST API. Mọi lệnh đều theo cú pháp:

```text
docker [OPTIONS] COMMAND [SUBCOMMAND] [ARGS...]
```

Từ `Docker 1.13+`, các lệnh đã được nhóm lại (ví dụ `docker container ls` thay cho `docker ps`). Cả hai cú pháp đều dùng được.

## 1. Thông tin hệ thống

```bash
docker version              # Phiên bản Client + Engine
docker info                 # Trạng thái toàn cục: số container, image, storage driver…
docker system df            # Dung lượng Docker đang dùng (image, container, volume, cache)
docker system df -v         # Chi tiết từng item
docker stats                # Monitor realtime CPU/RAM/IO của container
docker stats --no-stream    # Một snapshot, không stream
docker events               # Stream sự kiện Docker realtime (debug)
```

## 2. Quản lý Image

### 2.1 Pull / Push Image

```bash
docker pull nginx:1.27-alpine                # Tải image
docker pull --platform linux/amd64 nginx     # Chỉ định platform
docker push myrepo/myapp:1.0                 # Đẩy lên registry (cần login)
```

## 2.2 Liệt kê / Tra cứu Image

```bash
docker images                                # Liệt kê image local
docker image ls                              # Tương đương lệnh trên
docker images -a                             # Bao gồm cả intermediate layer
docker images --digests                      # Hiện cả digest
docker images --filter "dangling=true"       # Image mồ côi (không tag, không dùng)
docker image inspect nginx:1.27-alpine       # Toàn bộ metadata
docker image history nginx:1.27-alpine       # Layer history
docker search nginx                          # Tìm image trên Docker Hub
```

### 2.3 Tag / Build / Save / Load Image

```bash
docker tag nginx:1.27-alpine myrepo/nginx:custom    # Đặt tag mới
docker build -t myapp:1.0 .                         # Build từ Dockerfile
docker save myapp:1.0 -o myapp.tar                  # Export image ra file tar
docker load -i myapp.tar                            # Import từ tar
```

### 2.4 Xoá image

```bash
docker rmi nginx:1.27-alpine        # Xóa image (alias: docker image rm)
docker rmi -f nginx                 # Force xóa (kể cả khi có container dùng)
docker image prune                  # Xóa image dangling (không tag)
docker image prune -a               # Xóa tất cả image không được dùng bởi container nào
docker image prune -a --filter "until=24h"   # Xóa image cũ hơn 24 giờ
```

## 3. Quản lí Container

### 3.1 Các lệnh tạo và chạy Container

```bash
docker run nginx                              # Foreground, gắn STDOUT/STDERR
docker run -d nginx                           # Detached (chạy ngầm)
docker run -d -p 8080:80 nginx                # Map port host:container
docker run -d -p 127.0.0.1:8080:80 nginx      # Chỉ bind localhost
docker run -d --name web nginx                # Đặt tên container
docker run -it ubuntu:24.04 bash              # Interactive + TTY (vào shell)
docker run --rm ubuntu:24.04 echo "hello"     # Tự xóa sau khi exit
docker run -e MY_VAR=value nginx              # Biến môi trường
docker run --env-file .env nginx              # Load env từ file
docker run -v my-vol:/data nginx              # Named volume
docker run -v $(pwd)/src:/app/src nginx       # Bind mount
docker run --network my-net nginx             # Custom network
docker run --restart unless-stopped nginx     # Restart policy
docker run --memory="512m" --cpus="1.5" nginx # Giới hạn tài nguyên
docker run --user 1000:1000 nginx             # Chạy với UID:GID cụ thể
docker run --read-only nginx                  # Filesystem chỉ đọc
docker run --cap-drop ALL --cap-add NET_BIND_SERVICE nginx   # Giới hạn capability
docker run --health-cmd="curl -f http://localhost/" \
           --health-interval=30s nginx        # Healthcheck
```

**Note**: Lưu ý quan trọng khi dùng file

- Không nên commit file `.env` lên Git nếu chứa mật khẩu — nên thêm `.env` vào file `.gitignore`.
- File `.env` không hỗ trợ comment bắt đầu bằng `#` trên một số phiên bản Docker cũ — nên tránh dùng comment nếu không chắc.
- Có thể kết hợp cả `--env-file` và `-e` trong cùng một lệnh — nếu trùng tên biến, `-e` sẽ ghi đè giá trị trong file.

- Tiếp  theo, thực hành lệnh gắn volume trên máy Host (Do Docker quản lí) mount với thư mục `/data` trong cointainer, để sau khi xoá container cũng không mất dữ liệu:


  - Tiếp theo, xoá container:

  ```bash

  ```

  - Tạo container mới và mount cùng volume cũ:

  ```bash
  docker run -d --name web2 -v my-vol:/usr/share/nginx/html nginx
  ```

  - Cuối cùng kiểm tra dữ liệu còn không:

  ```bash
  docker exec web2 cat /usr/share/nginx/html/index.html
  ```

- Lệnh dùng để mount trực tiếp một thư mục thật trên **máy host** vào bên trong container — đây chính là kiểu bind mount mà mình có nhắc ở câu trước, khác với **volume do Docker tự quản lý**:

  - Đầu tiên, check xem thư mục ta đứng là ở đâu:

  ```bash
  pwd
  
  # Output:/home/docker
  ```

  - Giả sử ta tạo thư mục `myapp` để hình dung như đang làm việc với dự án ta phát triển 1 ứng dụng Node.js

  ```bash
  mkdir myapp
  ```

  - Lúc này cấu trúc thư mục dự án sẽ phân như sau:

  ```text
  /home/docker/myapp/
  ├── src/
  │   ├── index.js
  │   └── utils.js
  ├── package.json
  ```

  - Ta chạy để bind mount thư mục trên máy Host ứng với thư mục dự án:

  ```bash
  cd /home/docker/myapp
  docker run -it -v $(pwd)/src:/app/src -w /app node sh
  ```

  - Thử sửa file ngay trên máy host (không cần vào container):

  ```bash
  sudo chown -R docker:docker src
  echo "console.log('Hello from host')" >> src/index.js
  ```

  - Rồi thử vào container kiểm tra:

  ```bash
  docker exec -it <container_id> cat /app/src/index.js
  ```

  =>  Bạn sẽ thấy dòng vừa thêm xuất hiện ngay lập tức, dù bạn sửa file từ bên ngoài container. Đây chính là điểm mạnh nhất của bind mount: dev code ở máy host bằng VS Code quen thuộc, nhưng **chạy/test** trong môi trường container — rất phổ biến khi phát triển phần mềm.

**Note2**: Lưu ý dùng trong thực tế

- Không dùng bind mount kiểu này cho production — vì phụ thuộc vào cấu trúc thư mục của máy host, không portable.
- Thường kết hợp bind mount này với Dockerfile để dev có "hot reload" — sửa code là thấy kết quả ngay, không cần build lại image.
- Trên Windows (PowerShell), `$(pwd)` không hoạt động giống hệt — cần dùng `${PWD}` (PowerShell) hoặc `%cd%` (cmd) thay thế.

**Note 3**:

- Khác với volume thì ta cần phải tạo trước network thì mới có thể gán nó vào container
- Ngoài ra, phải dừng/xóa hết container đang dùng network đó trước, nếu không sẽ báo lỗi "network has active endpoints".

- Tiếp theo, ta tìm hiểu lệnh set policy restart cho container (Trong trường hợp, container bị dừng vì lí do nào đó sẽ restart lại)

  - Ví dụ:

  ```bash
  docker run --restart unless-stopped nginx
  ```

  - `--restart`: flag để chỉ định chính sách restart.
  - `unless-stopped`: container sẽ tự khởi động lại trong mọi trường hợp (container bị crash, Docker daemon restart, máy host reboot,...) NGOẠI TRỪ khi bạn chủ động dừng nó bằng tay (docker stop).

  - Ngoài ra, có 1 số flag của trường `--restart`:

| Giá trị          | Ý nghĩa                                                                                             |
| ---------------- | ----------------------------------------------------------------------------------------------------- |
| `no`             | Mặc định. Không tự động khởi động lại container trong bất kỳ trường hợp nào.                                                                                                        |
| `on-failure`     | Chỉ khởi động lại nếu container thoát với lỗi (exit code khác `0`).                                                                                                                 |
| `on-failure:5`   | Giống `on-failure`, nhưng chỉ thử khởi động lại tối đa **5 lần**.                                                                                                                   |
| `always`         | Luôn tự khởi động lại container. Nếu Docker daemon khởi động lại (ví dụ sau khi reboot máy), container cũng sẽ tự chạy lại, ngay cả khi trước đó bạn đã `docker stop` nó.           |
| `unless-stopped` | Giống `always`, nhưng nếu bạn **`docker stop` thủ công**, Docker sẽ ghi nhớ trạng thái đó và **không tự khởi động lại** container sau khi Docker daemon hoặc máy chủ khởi động lại. |

=> Trong production người ta luôn sử dụng `unless-stopped`.

- Tiếp theo, chạy container vưới `UID`:`GID` cụ thể:
  
  - Trong Dockerfile:
  
  ```bash
  RUN chown -R 1000:1000 /var/cache/nginx /var/run /var/log/nginx
  USER 1000
  ```

  - Ví dụ:

  ```bash
  docker run --user 1000:1000 nginx
  ```

  - Số đầu (1000) là UID (User ID) hay là user Docker
  - Số sau (1000) là GID (Group ID)
  - Cú pháp: --user <UID>:<GID>

=> Chức năng chính lệnh này:

- Nếu ứng dụng bên trong container có lỗ hổng bảo mật, và kẻ tấn công thoát được ra khỏi container (container escape), họ sẽ có quyền root trên chính host (cực kỳ nguy hiểm).
- Bất kỳ file nào container tạo ra (qua bind mount) đều mang quyền root, gây khó khăn khi thao tác từ host (như ta đã gặp ở trên).

- Tiếp theo, chạy container với **File-system** `read-only`

```bash
docker run -d --name web --read-only \
  --tmpfs /var/cache/nginx \
  --tmpfs /var/run \
  --tmpfs /tmp \
  nginx
```

![Docker](./images/Docker_44.png)

**Note 4**: Nếu ta chạy lệnh `docker run --read-only nginx` -> Rất có thể nginx sẽ báo lỗi hoặc không khởi động được, vì nginx cần ghi vào một số thư mục tạm như `/var/cache/nginx`, `/var/run`, `/tmp` để hoạt động (lưu PID file, cache,...).

**Note 5**: Với mỗi image ứng dụng khcas nhau thì thư mục ghi tạm khác nhau.

=> **Cách khắc phục**: dùng thêm `--tmpfs` để cấp phát vùng nhớ tạm (RAM) cho những thư mục cụ thể cần ghi.

=> `--tmpfs /path`: tạo một filesystem tạm nằm trong RAM tại đường dẫn đó, container được ghi thoải mái vào đây, nhưng dữ liệu sẽ mất hết khi container dừng (đúng ý đồ — vì đây chỉ là cache/tạm, không phải dữ liệu cần giữ).

=> Ngoài ra, kết hợp `--read-only` + volume cho dữ liệu thật sự cần giữ (Giả dụ ví dụ MySQL):

```bash
docker run -d --name my-mysql \
  --read-only \
  --tmpfs /tmp \
  --tmpfs /var/run/mysqld \
  -v mysql-data:/var/lib/mysql \
  --env-file mysql.env \
  mysql
```

- Tiếp theo, chạy container giới hạn Capacility

  - Ví dụ:

  ```bash
  docker run --cap-drop ALL \
  --cap-add NET_BIND_SERVICE \
  --cap-add CHOWN \
  --cap-add SETUID \
  --cap-add SETGID \
  -p 8080:80 nginx
  ```

  => Lệnh này chạy container nginx với nguyên tắc "least privilege" (đặc quyền tối thiểu) bằng cách kiểm soát Linux capabilities — các quyền hạn cấp thấp của kernel mà bình thường tiến trình root trong container sẽ có toàn bộ.

  - Trong đó: `--cap-drop ALL`:Loại bỏ toàn bộ capabilities mặc định mà Docker cấp cho container (khoảng 14 quyền như CHOWN, KILL, NET_RAW, SETUID,...)
  - `--cap-add NET_BIND_SERVICE`(Chỉ cấp lại một quyền duy nhất): Cho phép tiến trình bind vào các cổng < `1024` (như cổng `80`, `443`) mà không cần chạy full quyền root
  - `nginx`: Image chạy

### 3.2 Các lệnh Quản lí vòng đời

```bash
docker ps                       # Container đang chạy
docker ps -a                    # Tất cả (cả đã dừng)
docker ps -q                    # Chỉ ID (dùng để pipe)
docker ps --filter "status=exited"
docker ps --format "table {{.Names}}\t{{.Status}}\t{{.Ports}}"

docker stop web                 # SIGTERM, chờ 10s, SIGKILL
docker stop -t 30 web           # Tăng timeout lên 30s
docker start web                # Khởi động lại container đã dừng
docker restart web              # Stop rồi start
docker pause web                # Freeze process (SIGSTOP qua cgroups freezer)
docker unpause web              # Resume
docker kill web                 # SIGKILL ngay lập tức
docker kill -s SIGHUP web       # Gửi signal khác

docker rm web                   # Xóa container đã dừng
docker rm -f web                # Force xóa container đang chạy
docker rm $(docker ps -aq)      # Xóa tất cả container
```

### 3.6 Commit / Export Container

```bash
docker commit web my-image:custom        # Tạo image từ container hiện tại (debug only, không dùng cho production)
docker export web -o web.tar             # Export filesystem container ra tar (mất history layer)
docker import web.tar my-image:flat      # Import flat tar thành image
```

Ta đóng gói cả container(đóng gói trạng thái hiện tại của container web - bao gồm mọi thay đổi filesystem đã xảy ra kể từ lúc chạy thành 1 image mới) thành 1 image để tạo ra nhiều container clone khác:(Dùng cho debug, không dùng cho production)

- Có thể thêm metadata khi commit:

```bash
docker commit \
  --author "Nguyen Van A <a@example.com>" \
  --message "Add curl and disable server_tokens" \
  --change='CMD ["nginx", "-g", "daemon off;"]' \
  web my-image:custom
```

![Docker](./images/Docker_76.png)

Tiếp theo, ta Export filesystem container ra tar(mất history layer):

- `TAR` = `Tape ARchive` — một định dạng file dùng để gộp nhiều file/thư mục thành 1 file duy nhất, giữ nguyên cấu trúc thư mục và permissions gốc.

![Docker](./images/Docker_77.png)

=> Lệnh này xuất toàn bộ filesystem của container web (tại thời điểm hiện tại) thành 1 file `.tar` duy nhất, lưu ra đường dẫn web.tar.

=> Do nó không giữ lại metadata lên nó dùng để backup/di chuyển filesystem thô, hoặc audit(quyền).

## 4. Các lệnh quản lí Volume

```bash
docker volume create my-data                   # Tạo volume
docker volume create --driver local \
       -o type=nfs -o o=addr=10.0.0.1,rw \
       -o device=:/exports/data my-nfs         # Volume với driver/option

docker volume ls                               # Liệt kê
docker volume ls --filter "dangling=true"      # Volume không gắn container nào
docker volume inspect my-data                  # Xem chi tiết
docker volume rm my-data                       # Xóa
docker volume prune                            # Xóa volume không dùng
docker volume prune --filter "label!=keep"     # Trừ volume có label `keep`

# Gắn volume vào cointainer
docker run --mount source=my-data,target=/app/data ...

# Xóa nhiều volume cùng lúc / force
docker volume rm $(docker volume ls -q -f dangling=true)
docker volume rm -f my-data

# Xem volume đang gắn ở container nào
docker inspect --format '{{ json .Mounts }}' <container>

# Backup / restore dữ liệu trong volume
docker run --rm -v my-data:/data -v $(pwd):/backup alpine \
  tar czf /backup/backup.tar.gz -C /data .

docker run --rm -v my-data:/data -v $(pwd):/backup alpine \
  tar xzf /backup/backup.tar.gz -C /data
```

## 5. Các lệnh Quản lí Network

```bash
docker network create my-net                          # Bridge network
docker network create --driver overlay swarm-net      # Overlay (cần swarm)
docker network create --subnet=172.20.0.0/16 \
       --gateway=172.20.0.1 my-net                    # Chỉ định subnet/gateway

docker network ls                                     # Liệt kê
docker network inspect my-net                         # Chi tiết (gồm container đang gắn)

docker network connect my-net web                     # Gắn container vào network
docker network connect --ip 172.20.0.10 my-net web   # Gắn với IP cố định
docker network disconnect my-net web                  # Bỏ gắn

docker network rm my-net                              # Xóa
docker network prune                                  # Xóa network không dùng

# Gắn container vào network ngay lúc tạo (thay vì connect sau)
docker run --network my-net --name web nginx
docker run --network my-net --network-alias webserver nginx   # đặt alias DNS trong network

# Container giao tiếp bằng tên - Chỉ hoặt dộng với user define network
docker network create my-net
docker run -d --network my-net --name db postgres
docker run -d --network my-net --name app myapp
# app có thể ping/connect tới "db" bằng tên, không cần --link

# Gắn container vào nhiều network
docker network connect net1 web
docker network connect net2 web
docker inspect --format '{{json .NetworkSettings.Networks}}' web

# Tuỳ chọn driver Option nâng cao khi tạo
docker network create --driver bridge \
  -o com.docker.network.bridge.name=br0 \
  --internal my-net                          # --internal: cô lập, không ra ngoài internet

# Xem nhiều network/lọc khi prune
docker network prune --filter "until=24h"
docker network rm $(docker network ls -q --filter "type=custom")

# Xem network mặc định (bridge, host, none)
docker network ls   # sẽ thấy bridge, host, none luôn tồn tại sẵn
docker run --network host ...    # dùng trực tiếp network của host, không NAT
docker run --network none ...    # không có network

# Debug network container đang chạy
docker exec web ip addr show
docker exec web cat /etc/resolv.conf
```

## 8. Docker Compose

```bash
# Life Cycle
docker compose up                       # Khởi động foreground (xem log)
docker compose up -d                    # Detached
docker compose up -d --build            # Build lại image trước khi start
docker compose up -d --force-recreate   # Tạo lại container kể cả khi không đổi
docker compose up -d --no-deps web      # Không khởi động dependency
docker compose up -d web db             # Chỉ khởi động service được chỉ định

docker compose down                     # Dừng và xóa container + network
docker compose down -v                  # Bao gồm cả volume (MẤT DATA)
docker compose down --rmi all           # Xóa cả image

docker compose stop                     # Dừng (giữ container)
docker compose start                    # Khởi động lại container đã stop
docker compose restart web              # Restart 1 service
docker compose pause web                # Freeze process
docker compose unpause web

#  Inspect / Logs / Exec
docker compose ps                       # Trạng thái service
docker compose ps -a                    # Bao gồm cả stopped
docker compose top                      # Process trong từng service
docker compose stats                    # CPU/RAM realtime

docker compose logs                     # Log tất cả (1 lần)
docker compose logs -f                  # Follow
docker compose logs -f --tail 100 web   # 100 dòng cuối của `web`
docker compose logs --since 10m         # Log 10 phút gần nhất

docker compose exec web bash            # Vào shell service đang chạy
docker compose exec -u root web bash    # Với root
docker compose run --rm web npm test    # Tạo container mới chạy lệnh (rồi xóa)
docker compose run --rm web sh -c "echo $DB_HOST"

# Build/Pull/Push
docker compose build                    # Build tất cả service có `build:`
docker compose build --no-cache web
docker compose build --pull             # Pull base image mới nhất
docker compose pull                     # Pull image cho tất cả service
docker compose pull db                  # Pull image cho service cụ thể
docker compose push                     # Push image (cần đã build + login)

# Config / Validation
docker compose config                   # In ra config đã merge và validate
docker compose config --services        # Liệt kê tên service
docker compose config --volumes
docker compose config --quiet           # Chỉ kiểm tra syntax (silent)

# Scale
docker compose up -d --scale web=3      # Chạy 3 instance `web` (cần dùng `ports` dạng range hoặc bỏ ports)
```

=> Các lệnh này ta check trong lab **deploy app thực tế** trong phần **Lab Docker**.
