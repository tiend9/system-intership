# SERVICE TRONG K8S

## I. SERVICE LÀ GÌ?

**Service** là một đối tượng (**Object**) trong Kubernetes dùng để **cung cấp một điểm truy cập (Endpoint) ổn định** đến một hoặc nhiều Pod.

Do Pod có tính chất **ephemeral (tạm thời)**:

- Pod có thể bị xóa và tạo lại bất cứ lúc nào.
- Mỗi Pod có IP riêng và IP sẽ thay đổi khi Pod được tạo lại.

→ Service giải quyết vấn đề này bằng cách cung cấp:

- Một **Cluster IP** cố định.
- Một **DNS** cố định.
- **Load Balancing** giữa các Pod backend.

> **Hiểu đơn giản:** Pod thay đổi liên tục, còn Service là "địa chỉ cố định" để các ứng dụng luôn có thể kết nối.

## II. HOW SERVICE WORK ?

Ví dụ:

```text
Client
   │
   ▼
Service (10.96.0.20)
   │
 ┌─┴─────────────┐
 ▼               ▼
Pod A         Pod B
10.244.1.5    10.244.2.9
```

Service sẽ:

- Theo dõi các Pod thông qua **Label Selector**.
- Tự động cập nhật danh sách Pod khi Pod được tạo hoặc xóa.
- Phân phối request đến các Pod đang hoạt động.

## III. SELECTOR

Thông thường Service chọn Pod bằng **Label Selector**.

Ví dụ:

```yaml
spec:
  selector:
    app: myapp
```

Các Pod:

```yaml
metadata:
  labels:
    app: myapp
```

sẽ tự động trở thành backend của Service.

## IV. ENDPOINTSLICE

Service **không lưu trực tiếp danh sách Pod**.

Thay vào đó Kubernetes tạo các **EndpointSlice**, chứa danh sách các Pod backend.

```text
Service
     │
     ▼
EndpointSlice
 ├── 10.244.1.5
 ├── 10.244.2.9
 └── 10.244.3.7
```

Khi Pod thay đổi:

- EndpointSlice tự động cập nhật.
- Service luôn biết Pod nào đang sẵn sàng nhận traffic.

> **Lưu ý:** EndpointSlice là phiên bản mới thay thế API Endpoints (đã deprecated).

## V. SERVICE DISCOVERY

Kubernetes hỗ trợ hai cách để Pod tìm Service.

### 1. DNS (Khuyến nghị)

Ví dụ:

```text
my-service.default.svc.cluster.local
```

Hoặc nếu cùng namespace:

```text
my-service
```

**CoreDNS** sẽ tự động phân giải thành **ClusterIP**.

### 2. Environment Variables

Kubelet tạo các biến môi trường:

```yaml
MY_SERVICE_SERVICE_HOST=10.96.0.20
MY_SERVICE_SERVICE_PORT=80
```

> Hiện nay DNS là cách được sử dụng phổ biến hơn.

## VI. Port Mapping

Ví dụ:

```yaml
ports:
- port: 80
  targetPort: 9376
```

```text
Client
   │
   ▼
Service:80
   │
   ▼
Container:9376
```

Ý nghĩa:

| Thuộc tính | Ý nghĩa |
|------------|----------|
| port | Port mà Service lắng nghe |
| targetPort | Port của container |

Nếu không khai báo:

```text
targetPort = port
```

## VII. Các loại Service

### 7.1 ClusterIP (Mặc định)

```text
Client trong Cluster
        │
        ▼
   ClusterIP
        │
        ▼
       Pods
```

**Đặc điểm**:

- Chỉ truy cập được từ bên trong Cluster.
- Có Cluster IP.
- Là loại Service được sử dụng nhiều nhất.

Ví dụ:

```yaml
spec:
  type: ClusterIP
```

### 7.2 NodePort

**NodePort** mở một cổng trên **tất cả Node**.

```text
Internet
     │
NodeIP:30080
     │
     ▼
 Service
     │
     ▼
    Pods
```

Ví dụ:

```yaml
spec:
  type: NodePort

  ports:
  - port: 80
    nodePort: 30080
```

Mặc định Kubernetes sử dụng dải:

```text
30000 - 32767
```

Truy cập:

```text
http://NodeIP:30080
```

Thường dùng:

- Lab
- Bare Metal
- Testing

### 7.3 LoadBalancer

```text
Internet
     │
     ▼
LoadBalancer
     │
     ▼
 Service
     │
     ▼
    Pods
```

**Đặc điểm**:

- Cloud Provider tạo Load Balancer bên ngoài Cluster.
- Có External IP.
- Thích hợp Production.

**Ví dụ**:

```yaml
spec:
  type: LoadBalancer
```

### 7.4 ExternalName

Không chuyển tiếp traffic.

Chỉ tạo bản ghi **DNS CNAME**.

Ví dụ:

```yaml
spec:
  type: ExternalName
  externalName: mydb.example.com
```

Khi Pod truy cập:

```text
my-service
```

DNS sẽ trả về:

```text
mydb.example.com
```

Thường dùng khi:

- Database nằm ngoài Kubernetes.
- Gọi dịch vụ bên ngoài Cluster.

### 7.5 Headless Service

Khai báo:

```yaml
spec:
  clusterIP: None
```

Đặc điểm:

- Không có Cluster IP.
- Không Load Balancing.
- DNS trả về IP của từng Pod.

Ví dụ:

```text
Pod1
10.1.1.1

Pod2
10.1.1.2

Pod3
10.1.1.3
```

DNS sẽ trả về:

```
10.1.1.1
10.1.1.2
10.1.1.3
```

Thường dùng cho:

- StatefulSet
- Kafka
- Cassandra
- Elasticsearch
- Database Cluster

## VII. SERVICE KHÔNG CÓ SELECTOR

Thông thường Service sử dụng Selector.

Tuy nhiên có thể bỏ Selector:

```yaml
spec:
  ports:
  - port: 80
```

Sau đó tự tạo **EndpointSlice**:

```yaml
kind: EndpointSlice
```

Ứng dụng:

- Database ngoài Cluster.
- Server vật lý.
- Dịch vụ ở Cluster khác.

## VIII. LOAD BALANCING

Service tự động phân phối request giữa các Pod.

Ví dụ:

```text
Request 1 → Pod A

Request 2 → Pod B

Request 3 → Pod C
```

Client không cần biết Pod nào xử lý request.

## VII. SESSION AFFINITY

Mặc định:

```text
Client A

↓

Pod A

↓

Lần sau

↓

Pod B
```

Nếu bật Session Affinity:

```text
Client A

↓

Pod A

↓

Lần sau

↓

Pod A
```

**Giúp duy trì phiên làm việc** (Sticky Session).

## VIII. LUỒNG TỔNG QUÁT

```text
Client
   │
   ▼
DNS (my-service)
   │
   ▼
ClusterIP
   │
   ▼
Service
   │
   ▼
EndpointSlice
   │
 ┌─┴─────────────┐
 ▼               ▼
Pod A         Pod B
```

## IX. TỔNG KẾT

- Service cung cấp **IP và DNS ổn định** cho một nhóm Pod.
- Pod có thể thay đổi nhưng Service vẫn giữ nguyên địa chỉ truy cập.
- Service sử dụng **Label Selector** để tìm Pod.
- **EndpointSlice** lưu danh sách Pod backend và được cập nhật tự động.
- Hỗ trợ **Service Discovery** thông qua DNS hoặc Environment Variables (DNS được khuyến nghị).
- Tự động **Load Balancing** giữa các Pod đang sẵn sàng.
- Có 4 loại Service chính:
  - **ClusterIP**: Chỉ truy cập nội bộ.
  - **NodePort**: Truy cập qua `NodeIP:Port`.
  - **LoadBalancer**: Truy cập từ Internet thông qua Load Balancer.
  - **ExternalName**: Ánh xạ Service tới một tên miền bên ngoài.
- **Headless Service** (`clusterIP: None`) không thực hiện Load Balancing mà trả về trực tiếp IP của từng Pod.
