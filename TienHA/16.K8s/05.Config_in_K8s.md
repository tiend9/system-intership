# CONFIGURATION IN K8S

**Configuration** là nhóm tài nguyên dùng để cấu hình ứng dụng chạy trong Pod mà không cần sửa image container. Kubernetes tách phần **configuration** ra khỏi **application code**, giúp dễ triển khai, bảo trì và bảo mật.

**Các loại Configuration phổ biến trong K8S** ta sẽ tìm  hiểu sau đây.

## I. CONFIG MAP

### 1. Khái niệm

**ConfigMap** là một **API Object** dùng để lưu trữ dữ liệu cấu hình **không nhạy cảm (non-confidential)** dưới dạng **key-value**.

ConfigMap giúp **tách cấu hình của ứng dụng khỏi container image**, giúp ứng dụng dễ dàng triển khai ở nhiều môi trường khác nhau mà không cần build lại image.

> **Lưu ý:** ConfigMap **không cung cấp cơ chế mã hóa hoặc bảo mật**. Nếu dữ liệu là thông tin nhạy cảm (password, token, API key...), nên sử dụng **Secret**.

### 2. Đặc điểm

- Lưu dữ liệu dưới dạng **key-value**.
- Có hai trường dữ liệu:
  - `data`: lưu chuỗi UTF-8.
  - `binaryData`: lưu dữ liệu nhị phân dưới dạng Base64.
- Kích thước tối đa của một ConfigMap là **1 MiB**.
- ConfigMap phải nằm **cùng Namespace** với Pod sử dụng nó.
- Từ Kubernetes **v1.19**, ConfigMap hỗ trợ thuộc tính **immutable**.

### 3. Các cách sử dụng ConfigMap trong Pod

ConfigMap có thể được sử dụng theo 4 cách:

1. Truyền vào **command** hoặc **args** của container.
2. Làm **Environment Variables**.
3. Mount thành **file** trong Volume (read-only).
4. Ứng dụng đọc trực tiếp thông qua **Kubernetes API**.

### 4. Sử dụng ConfigMap làm Volume

- Mount ConfigMap vào một thư mục trong container.
- Mỗi key trong ConfigMap sẽ trở thành một file.
- Có thể chỉ định `items` để chỉ mount một số key.
- Nếu không khai báo `items`, tất cả các key sẽ được tạo thành file.

### 5. Sử dụng ConfigMap làm Environment Variables

Có hai cách:

- `env`: lấy từng key cụ thể trong ConfigMap.
- `envFrom`: import toàn bộ key-value trong ConfigMap thành các biến môi trường.

### 6. Cập nhật ConfigMap

#### Khi mount dưới dạng Volume

- Khi ConfigMap được cập nhật, dữ liệu trong Volume sẽ được cập nhật tự động sau một khoảng thời gian đồng bộ của kubelet.

> **Lưu ý:** Nếu mount bằng `subPath` thì **không nhận được cập nhật**.

#### Khi sử dụng Environment Variables

- Giá trị **không được cập nhật tự động**.
- Muốn nhận giá trị mới phải **restart Pod**.

### 7. Immutable ConfigMap

Từ Kubernetes **v1.21**, có thể đặt:

```yaml
immutable: true
```

Sau khi ConfigMap được đánh dấu là **immutable**:

- Không thể chỉnh sửa `data` hoặc `binaryData`.
- Không thể đổi lại `immutable` về `false`.
- Muốn thay đổi nội dung phải **xóa và tạo lại ConfigMap**.
- Sau khi tạo lại ConfigMap, nên **recreate Pod** để sử dụng ConfigMap mới.

### 8. Tóm tắt

| Nội dung | Mô tả |
|----------|------|
| Mục đích | Lưu cấu hình không nhạy cảm |
| Kiểu dữ liệu | Key-Value |
| Giới hạn kích thước | 1 MiB |
| Phải cùng Namespace với Pod | Có |
| Cách sử dụng | Command/Args, Environment Variables, Volume, Kubernetes API |
| Volume | Tự động cập nhật khi ConfigMap thay đổi |
| Environment Variables | Không tự cập nhật, cần restart Pod |
| Immutable | Không thể chỉnh sửa sau khi tạo (`immutable: true`) |
| Không dùng cho | Password, Token, API Key (nên dùng Secret) |

## II. Secret

### 1.Khái niệm

- **Secret** là đối tượng Kubernetes dùng để lưu trữ **dữ liệu nhạy cảm** như:

  - Password
  - Token
  - Key

- Secret tương tự **ConfigMap**, nhưng được thiết kế dành riêng cho dữ liệu bảo mật.
- Secret được tạo độc lập với Pod, giúp giảm nguy cơ lộ thông tin khi tạo, xem hoặc chỉnh sửa Pod.

> **Lưu ý:** Mặc định Secret **không được mã hóa trong etcd**. Nên:
>
> - Bật **Encryption at Rest**
> - Áp dụng **RBAC** theo nguyên tắc quyền tối thiểu
> - Hạn chế container được truy cập Secret
> - Có thể dùng hệ thống quản lý Secret bên ngoài

### 2.  Công dụng của Secret

**Secret** thường được dùng để:

- Truyền dữ liệu vào Pod thông qua **Environment Variables**
- Mount thành **file trong Volume**
- Lưu thông tin đăng nhập như:
  - Password
  - SSH Key
  - Token
- Lưu thông tin để **pull image từ Private Registry**
- Được Kubernetes Control Plane sử dụng (ví dụ: Bootstrap Token)

### 3. Các loại Secret

| Type | Mục đích |
|-------|----------|
| Opaque | Dữ liệu tùy ý do người dùng định nghĩa |
| kubernetes.io/service-account-token | ServiceAccount Token |
| kubernetes.io/dockercfg | Docker config cũ |
| kubernetes.io/dockerconfigjson | Docker config mới |
| kubernetes.io/basic-auth | Username / Password |
| kubernetes.io/ssh-auth | SSH Private Key |
| kubernetes.io/tls | TLS Certificate và Private Key |
| bootstrap.kubernetes.io/token | Bootstrap Token |

> Nếu không chỉ định `type`, Kubernetes sẽ mặc định là **Opaque**.

### 4. Tạo Secret

Có thể tạo Secret bằng:

- kubectl
- File YAML
- Kustomize

### 5. Sử dụng Secret

Secret có thể được Pod sử dụng theo nhiều cách:

- Mount thành **Volume**
- Đưa vào **Environment Variables**
- Dùng làm **imagePullSecrets** để pull image từ Private Registry

#### a. Secret dưới dạng Volume

- Secret được mount thành file trong container.
- Khi Secret được cập nhật, dữ liệu trong Volume sẽ được cập nhật theo cơ chế **eventually consistent**.
- Nếu mount bằng **subPath** thì **không tự động cập nhật**.

#### b. Secret dưới dạng Environment Variable

- Có thể đưa từng key của Secret vào biến môi trường bằng:
  - `env.valueFrom.secretKeyRef`
- Chỉ các key hợp lệ mới được tạo thành Environment Variable.

#### c. imagePullSecrets

- Dùng để lưu thông tin xác thực khi pull image từ Private Registry.
- Được khai báo trong trường `imagePullSecrets` của Pod.
- Có thể gắn tự động thông qua **ServiceAccount**.

### 6. Optional Secret

- Secret có thể được đánh dấu là **optional**.
- Nếu Secret optional không tồn tại thì Pod vẫn chạy.
- Mặc định Secret là **required**.

### 7. Immutable Secret(Đặt trạng thái bất biến)

- Có thể đặt:

```yaml
immutable: true
```

- Khi Secret đã immutable:
  - Không thể sửa dữ liệu.
  - Chỉ có thể xóa rồi tạo lại Secret mới.
  - Khuyến nghị tạo lại Pod sau khi tạo Secret mới.

### 8. Giới hạn

- Kích thước tối đa của một Secret là **1 MiB**.
- Tên Secret phải là **DNS subdomain hợp lệ**.
- `data` chứa giá trị **Base64**.
- Có thể dùng `stringData` để nhập dữ liệu dạng plain text, Kubernetes sẽ tự chuyển sang `data`.

### 9. Bảo mật

- Secret chỉ được gửi tới Node khi Pod trên Node đó cần sử dụng.
- Khi mount vào Pod, kubelet lưu Secret trong **tmpfs** thay vì ghi xuống ổ đĩa.
- Pod chỉ truy cập được các Secret mà nó được khai báo sử dụng.
- Nên giới hạn quyền truy cập bằng **RBAC** và áp dụng nguyên tắc **Least Privilege**.

## III. RESOURCE MANAGEMENT FOR POD AND CONTAINERS

**Kubernetes** cho phép giới hạn tài nguyên mà mỗi container được phép sử dụng.

Hai tài nguyên quan trọng nhất:

- CPU
- Memory

### 1. Resource Request

Lượng tài nguyên tối thiểu container yêu cầu.

Ví dụ:

```yaml
resources:
  requests:
    cpu: "500m"
    memory: "256Mi"
```

**Scheduler** sẽ chỉ đặt Pod lên Node còn đủ tài nguyên.

### 2. Resource Limit

Giới hạn tài nguyên tối đa container được phép dùng.

```yaml
resources:
  limits:
    cpu: "1"
    memory: "512Mi"
```

### 3. CPU

Nếu vượt limit CPU

→ Kubernetes sẽ **Throttle CPU**

Container vẫn chạy nhưng chậm hơn.

### 4. Memory

Nếu vượt limit Memory

→ Container bị **OOMKilled**

Pod sẽ restart theo RestartPolicy.

### 5. ResourceQuota

Dùng để giới hạn tổng tài nguyên của một Namespace.

Ví dụ:

- Tổng CPU
- Tổng RAM
- Số Pod tối đa
- Số PVC

### 6. LimitRange

Đặt:

- Default Request
- Default Limit
- Min/Max CPU
- Min/Max Memory

cho Pod hoặc Container trong Namespace.

## IV. kubeconfig

### 1. Khái niệm

`kubeconfig` là file cấu hình để kubectl kết nối tới Kubernetes Cluster.

Thông thường:

```bash
~/.kube/config
```

### 2. kubeconfig chứa gì?

#### a. Cluster

Thông tin API Server

Ví dụ:

```text
https://192.168.1.100:6443
```

#### b. User

Thông tin xác thực

Có thể dùng:

- Certificate
- Token
- OIDC
- Exec Plugin

#### c. Context

Liên kết giữa:

```text
Cluster + User + Namespace
```

Một kubeconfig có thể chứa nhiều Context.

**Ví dụ**:

```text
dev-cluster
prod-cluster
staging-cluster
```

Chuyển nhanh:

```bash
kubectl config use-context prod
```

**Lợi ích**:

- Quản lý nhiều cluster
- Quản lý nhiều user
- Chuyển đổi môi trường nhanh
- Hỗ trợ RBAC
