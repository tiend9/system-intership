# LAB: XÂY DỰNG HỆ THỐNG 3 LỚP PHÂN VÙNG MẠNG, KÉO CODE + DB TỪ GITHUB, CÓ CACHE VÀ MONITORING (3_TIER-ARCHITECTURE)

Mục tiêu lab: dựng một hệ thống web app hoàn chỉnh trên nhiều máy chủ (hoặc mô phỏng bằng Docker/VM), tách biệt hoàn toàn mạng Frontend / Backend / Database / Cache / Monitoring, có firewall phân port rõ ràng, có CI/CD kéo source code từ GitHub, và phân quyền đúng chuẩn least-privilege ở mọi lớp.

## 1. Kiến trúc tổng quan

Nguyên tắc cốt lõi: **mỗi network chỉ được phép nói chuyện với network liền kề, qua đúng 1 port dịch vụ, theo đúng 1 chiều**. Không có network nào được phép "nhìn thấy" toàn bộ hệ thống trừ Monitoring (chỉ ở chế độ scrape, read-only) và Bastion (chỉ SSH quản trị).

## 2. Sơ đồ subnet / VLAN

| Network | CIDR | Thành phần | Truy cập từ Internet |
|---|---|---|---|
| Public/Edge | 10.0.0.0/24 | Firewall, Load Balancer | Có (80/443) |
| Frontend | 10.0.1.0/24 | LB, Web server | Không (chỉ qua Edge) |
| Backend | 10.0.2.0/24 | API server, CI/CD runner | Không |
| Database | 10.0.3.0/24 | Postgres/MySQL | Không |
| Cache | 10.0.4.0/24 | Redis | Không |
| Monitoring | 10.0.5.0/24 | Prometheus, Grafana, Alertmanager | Không (Grafana chỉ qua VPN) |
| Management | 10.0.10.0/24 | Bastion host | SSH whitelist IP admin |

Nếu dùng cloud (AWS/GCP/Azure): mỗi network ở trên map thành 1 subnet riêng trong VPC, có Security Group / NSG riêng. Nếu làm lab tại chỗ bằng Docker: mỗi network map thành 1 `docker network` riêng

## 3. Bảng firewall — phân port đầy đủ

Quy tắc: **deny all mặc định**, chỉ mở đúng rule liệt kê dưới đây (allow-list).

| # | Source | Destination | Port | Giao thức | Mục đích |
|---|---|---|---|---|---|
| 1 | 0.0.0.0/0 | Edge/LB | 443 | TCP | HTTPS public |
| 2 | 0.0.0.0/0 | Edge/LB | 80 | TCP | Redirect sang 443 |
| 3 | Frontend SG | Backend SG | 8080 | TCP | LB gọi API |
| 4 | Backend SG | DB SG | 5432 | TCP | API truy vấn Postgres |
| 5 | Backend SG | Cache SG | 6379 | TCP | API truy vấn Redis |
| 6 | Backend SG | Internet (chỉ github.com, registry docker) | 443 | TCP | Pull code/image từ GitHub |
| 7 | Monitoring SG | Frontend/Backend SG | 9100 | TCP | node_exporter scrape |
| 8 | Monitoring SG | DB SG | 9187 | TCP | postgres_exporter scrape |
| 9 | Monitoring SG | Cache SG | 9121 | TCP | redis_exporter scrape |
| 10 | Admin VPN/Bastion | Monitoring SG | 3000 | TCP | Truy cập Grafana |
| 11 | Bastion SG | Toàn bộ private subnet | 22 | TCP | SSH quản trị |
| 12 | Admin IP whitelist | Bastion SG | 22 | TCP | Vào bastion |
| — | Tất cả còn lại | Tất cả | * | * | **DENY (mặc định)** |

**Note 0**:

- DB và Cache **không bao giờ** có route trực tiếp ra Internet, kể cả outbound (trừ NTP/DNS nội bộ nếu cần).
- Chỉ Backend network được phép outbound tới GitHub — Frontend, DB, Cache không cần và không được phép.
- Monitoring chỉ có traffic 1 chiều "kéo" (scrape) vào các exporter port, không có quyền ghi/sửa dữ liệu ở node khác.

### Ví dụ iptables/ufw trên 1 server backend (Ubuntu):

```bash
# Backend server: chỉ nhận 8080 từ dải Frontend, nhận 9100 từ dải Monitoring, SSH từ Bastion
sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw allow from 10.0.1.0/24 to any port 8080 proto tcp
sudo ufw allow from 10.0.5.0/24 to any port 9100 proto tcp
sudo ufw allow from 10.0.10.0/24 to any port 22 proto tcp
sudo ufw enable
```

```bash
# DB server: chỉ nhận 5432 từ Backend, 9187 từ Monitoring
sudo ufw default deny incoming
sudo ufw allow from 10.0.2.0/24 to any port 5432 proto tcp
sudo ufw allow from 10.0.5.0/24 to any port 9187 proto tcp
sudo ufw allow from 10.0.10.0/24 to any port 22 proto tcp
sudo ufw enable
```

## 4. Phân quyền (IAM) — theo từng lớp

### 4.1 Cấp người dùng / vai trò tổ chức

| Role | Quyền |
|---|---|
| Admin | Toàn quyền hạ tầng, quản lý IAM, không có quyền truy cập DB production trực tiếp (phải qua bastion + audit log) |
| DevOps | Deploy, quản lý CI/CD, đọc log, không có quyền sửa firewall rule production trực tiếp (cần review) |
| Developer | Chỉ push code lên nhánh feature, không merge trực tiếp vào main, không SSH vào production |
| Read-only/Reporting | Chỉ đọc dashboard Grafana, không có quyền vào server |

### 4.2 Cấp hệ điều hành (server)

- Không dùng chung tài khoản `root` để SSH — mỗi người có user riêng, dùng `sudo` có log (`auditd`).
- SSH chỉ bằng **key-based auth**, tắt `PasswordAuthentication`.
- Mỗi service chạy bằng **service account riêng, không phải root** (ví dụ user `apiapp` chạy API, không có quyền sudo).

```bash
# Ví dụ tạo user chạy app, không có shell login, không sudo
sudo useradd -r -s /usr/sbin/nologin apiapp
sudo chown -R apiapp:apiapp /opt/api-app
```

### 4.3 Cấp database — phân quyền user rõ ràng

Không bao giờ dùng 1 user `postgres`/`root` cho toàn bộ hệ thống. Tạo tối thiểu 4 loại user:

```sql
-- User cho ứng dụng: chỉ CRUD trên schema của mình, không DDL, không DROP
CREATE ROLE app_user LOGIN PASSWORD '***';
GRANT CONNECT ON DATABASE appdb TO app_user;
GRANT SELECT, INSERT, UPDATE, DELETE ON ALL TABLES IN SCHEMA public TO app_user;

-- User chỉ đọc: cho reporting/BI/monitoring exporter
CREATE ROLE readonly_user LOGIN PASSWORD '***';
GRANT CONNECT ON DATABASE appdb TO readonly_user;
GRANT SELECT ON ALL TABLES IN SCHEMA public TO readonly_user;

-- User migration: chỉ CI/CD dùng để chạy migration, không dùng thường trực
CREATE ROLE migration_user LOGIN PASSWORD '***';
GRANT ALL PRIVILEGES ON DATABASE appdb TO migration_user;

-- Không expose superuser postgres ra ngoài network Backend, chỉ login local qua bastion
```

Bật `pg_hba.conf` để chỉ chấp nhận kết nối từ dải IP Backend network, ví dụ:

```text
# TYPE  DATABASE  USER          ADDRESS            METHOD
host    appdb     app_user      10.0.2.0/24        scram-sha-256
host    appdb     readonly_user 10.0.5.0/24         scram-sha-256
host    all       all           0.0.0.0/0           reject
```

### 4.4 Cấp GitHub — kéo source code an toàn

- **Không** dùng Personal Access Token cá nhân có full quyền để pull code trên server production.
- Dùng **Deploy Key** (SSH key riêng cho từng repo, read-only) gắn vào server backend/CI runner:

```bash
ssh-keygen -t ed25519 -f ~/.ssh/deploy_key_readonly -C "prod-backend-deploy"
# Add public key vào GitHub repo → Settings → Deploy keys → KHÔNG tick "Allow write access"
```

```bash
# Cấu hình SSH config trên server để chỉ dùng key này cho repo đó
cat >> ~/.ssh/config <<EOF
Host github.com
  IdentityFile ~/.ssh/deploy_key_readonly
  IdentitiesOnly yes
EOF

git clone git@github.com:your-org/your-repo.git /opt/api-app
```

- Nếu dùng GitHub Actions để deploy: tạo **GitHub App** hoặc **Fine-grained PAT** giới hạn đúng 1 repo, đúng quyền cần (contents: read, deployments: write), không cấp quyền admin org.
- Bật **branch protection** trên `main`: bắt buộc PR review, bắt buộc pass CI trước khi merge.
- Secrets (DB password, API key) **không bao giờ** commit vào repo — dùng GitHub Actions Secrets hoặc Vault/AWS Secrets Manager, inject qua biến môi trường lúc deploy.

### 4.5 Cấp Monitoring (Grafana)

- Grafana chỉ truy cập được qua VPN/Bastion, không public ra Internet.
- Phân quyền Grafana: `Admin` (toàn quyền dashboard), `Editor` (tạo dashboard), `Viewer` (chỉ xem) — gán theo role tổ chức ở mục 4.1.
- Prometheus không có UI ghi dữ liệu từ bên ngoài — chỉ nhận scrape pull, không nhận push tuỳ ý (trừ khi dùng Pushgateway có xác thực riêng).

## 5. Luồng CI/CD kéo code + deploy

1. Developer push code lên nhánh `feature/*` → mở PR vào `main`.
2. GitHub Actions chạy test (unit test, lint, security scan) trên PR.
3. Merge vào `main` (yêu cầu review + CI pass) → trigger workflow deploy.
4. Workflow build Docker image, push lên private registry (GitHub Container Registry hoặc self-hosted).
5. Deploy step SSH vào Backend server (qua Bastion hoặc CI runner có network riêng), pull image mới, restart container — **không** git clone trực tiếp code lên production nếu có thể, ưu tiên deploy bằng image đã build sẵn để tránh phải mở port ra GitHub trên chính server production.
6. Migration DB chạy riêng bằng `migration_user`, không lẫn với `app_user` runtime.

Ví dụ GitHub Actions workflow rút gọn:

```yaml
name: deploy
on:
  push:
    branches: [main]

jobs:
  build-and-deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Build image
        run: docker build -t ghcr.io/your-org/api:${{ github.sha }} .
      - name: Push image
        run: |
          echo "${{ secrets.GHCR_TOKEN }}" | docker login ghcr.io -u ${{ github.actor }} --password-stdin
          docker push ghcr.io/your-org/api:${{ github.sha }}
      - name: Deploy via SSH (qua bastion)
        uses: appleboy/ssh-action@v1
        with:
          host: ${{ secrets.BASTION_HOST }}
          username: deployer
          key: ${{ secrets.DEPLOY_SSH_KEY }}
          script: |
            ssh backend01 "docker pull ghcr.io/your-org/api:${{ github.sha }} && docker compose up -d api"
```

## 6. Cache layer (Redis)

- Redis chỉ nghe trên interface nội bộ (`bind 10.0.4.x`), không bind `0.0.0.0`.
- Bật `requirepass` hoặc dùng Redis ACL (Redis 6+) để tách quyền:

```redis
# redis.conf
bind 10.0.4.10
protected-mode yes
requirepass <strong-random-password>

# ACL: app chỉ được đọc/ghi cache namespace của mình
user appcache on >app-cache-pass ~cache:* +@read +@write -@admin
user default off
```

- Dùng cache cho: session store, kết quả query nặng (cache-aside pattern), rate-limiting counter.
- Backend gọi Redis qua timeout ngắn + circuit breaker để tránh cache sập kéo sập cả API.

## 7. Lab thực hành: mô phỏng bằng Docker (không cần nhiều VM)

Dùng Docker network để mô phỏng chia mạng thật — mỗi service chỉ join đúng network cần thiết, không có network "chung" nào chứa tất cả.

```yaml
# docker-compose.yml
version: "3.9"

networks:
  frontend_net:
  backend_net:
  db_net:
  cache_net:
  monitor_net:

services:
  nginx:
    image: nginx:latest
    networks: [frontend_net]
    ports: ["80:80", "443:443"]

  api:
    build: ./api          # source code kéo từ GitHub repo của bạn
    networks: [frontend_net, backend_net]   # API là cầu nối duy nhất giữa 2 lớp
    environment:
      - DB_HOST=db
      - REDIS_HOST=cache
    depends_on: [db, cache]

  db:
    image: postgres:16
    networks: [backend_net, db_net, monitor_net]   # chỉ để monitoring scrape, không cho backend đi thẳng qua monitor_net
    environment:
      - POSTGRES_PASSWORD=${DB_PASSWORD}
    volumes:
      - db_data:/var/lib/postgresql/data

  cache:
    image: redis:7
    command: ["redis-server", "--requirepass", "${REDIS_PASSWORD}"]
    networks: [backend_net, cache_net, monitor_net]

  prometheus:
    image: prom/prometheus
    networks: [monitor_net]
    volumes:
      - ./prometheus.yml:/etc/prometheus/prometheus.yml

  grafana:
    image: grafana/grafana
    networks: [monitor_net]
    ports: ["3000:3000"]   # trong thực tế: chỉ expose qua VPN, không public

volumes:
  db_data:
```

Điểm mấu chốt của mô phỏng này: `db` và `cache` **không** nằm trong `frontend_net` — Nginx không thể nào gọi thẳng tới database dù có cố tình cấu hình sai, vì Docker network đã cô lập ở tầng L3 ngay từ đầu. `api` là container **duy nhất** bắc cầu giữa `frontend_net` và `backend_net`.

Kiểm tra cô lập mạng sau khi dựng:

```bash
docker exec nginx ping -c1 db      # phải FAIL — không cùng network
docker exec api ping -c1 db        # phải OK
```

## 8. Monitoring stack chi tiết

| Component | Port | Vai trò |
|---|---|---|
| node_exporter | 9100 | Metric CPU/RAM/disk trên mỗi server |
| postgres_exporter | 9187 | Metric query, connection, replication lag |
| redis_exporter | 9121 | Metric hit rate, memory, eviction |
| cAdvisor | 8080 (nội bộ, khác dải với API 8080) | Metric container |
| Prometheus | 9090 | Thu thập & lưu trữ metric (chỉ nội bộ) |
| Alertmanager | 9093 | Gửi cảnh báo Slack/Email khi vượt ngưỡng |
| Grafana | 3000 | Dashboard trực quan (chỉ qua VPN) |

Ví dụ `prometheus.yml` scrape đúng từng network:

```yaml
scrape_configs:
  - job_name: backend
    static_configs:
      - targets: ["api:9100"]
  - job_name: postgres
    static_configs:
      - targets: ["db-exporter:9187"]
  - job_name: redis
    static_configs:
      - targets: ["cache-exporter:9121"]
```

Alert mẫu khi DB gần hết connection:

```yaml
groups:
  - name: db-alerts
    rules:
      - alert: HighDBConnections
        expr: pg_stat_activity_count > 80
        for: 2m
        labels:
          severity: warning
        annotations:
          summary: "Postgres connections gần đạt giới hạn"
```

- [ ] Grafana không public, chỉ qua VPN/Bastion
- [ ] Branch protection bật trên `main`: bắt buộc review + CI pass

- [ ] Có alert khi CPU/RAM/disk/connection DB vượt ngưỡng

## 10. Mở rộng khi lên production thật

- Thêm WAF (Web Application Firewall) trước Load Balancer.
- Database dùng replica (1 primary ghi, N replica đọc) — readonly_user trỏ vào replica để giảm tải primary.
- Cache dùng Redis Sentinel/Cluster để có failover.
- Log tập trung (Loki/ELK) đặt trong Monitoring network, có retention policy rõ ràng.
- Backup DB tự động, mã hoá, lưu ngoài network chính (offsite/S3), test restore định kỳ.
