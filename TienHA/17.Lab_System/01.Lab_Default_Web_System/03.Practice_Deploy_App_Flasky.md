### h. Giải thích 1 số giải pháp sử dụng

- **Promtail** là agent thu thập log của hệ sinh thái Grafana Loki — tương tự như Filebeat/Fluentd nhưng được thiết kế riêng để đẩy log vào Loki. Nó chạy trên từng máy/node, đọc log (từ file, journald, syslog, container...), gắn label kiểu Prometheus, rồi đẩy vào Loki để truy vấn bằng LogQL.

- **Prometheus**: Thu thập & lưu trữ metrics. Và xử lí số liệu dạng time-series (CPU, RAM, request/s...)

- **Loki**: Thu thập & lưu trữ log. Log dạng text, gắn label kiểu Prometheus.

- **Grafana**: Trực quan hóa & truy vấn bằng Dashboard hiển thị cả metrics lẫn log cùng lúc.

- **Blackbox Exporter** là một exporter của Prometheus dùng để "probe" (kiểm tra chủ động) các endpoint qua HTTP, HTTPS, DNS, TCP, ICMP, và gRPC. Khác với các exporter thông thường (tự expose metrics về chính nó), blackbox_exporter chủ động gửi request đến target để kiểm tra xem nó có "sống" và khỏe không, rồi trả về các metrics như thời gian phản hồi, status code, thời hạn chứng chỉ SSL, kết quả phân giải DNS...

- **Node Exporter** là exporter chính thức của Prometheus dùng để thu thập metrics phần cứng và hệ điều hành của máy chủ (Linux/Unix chủ yếu) — CPU, RAM, disk, network, filesystem, load average, v.v.

- **MinIO** là một object storage server mã nguồn mở, tương thích với Amazon S3 API. Nó cho phép bạn lưu trữ dữ liệu dạng object (file, ảnh, video, backup, dataset...) và truy cập qua các API/tool vốn được thiết kế cho AWS S3

- **auditd** là hệ thống audit của Linux kernel (Linux Audit Framework), dùng để ghi log chi tiết các sự kiện bảo mật trên hệ thống — ai làm gì, khi nào, từ đâu. Khác với syslog (log ứng dụng), auditd hoạt động ở mức kernel nên có thể theo dõi cả system call, truy cập file, thay đổi quyền, đăng nhập, thực thi lệnh, v.v. Thường dùng cho compliance (PCI-DSS, HIPAA, STIG) và điều tra sự cố bảo mật.

=> **node_exporter**, **blackbox_exporter**, **minio metrics**, **promtail** là nguồn dữ liệu, còn **Prometheus/Loki/Grafana** là nơi thu thập-lưu-hiển thị.

```bash
# LB làm CA nội bộ + TLS cho HA Proxy. Để HAProxy có thể phục vụ HTTPS (TLS) cho traffic đi vào từ FrontendNetwork thay vì HTTP
## Tạo Root CA trên LB
sudo mkdir -p /opt/ca/{private,certs}
cd /opt/ca

## File private key của CA nội bộ - Lộ ra toàn bộ hệ thống mất an toàn - Lên chỉ cho quyền đọc đối user devops
sudo openssl genrsa -out private/ca.key 4096
sudo chmod 400 private/ca.key

## Tạo crt để xác minh CA nội bộ 
sudo openssl req -x509 -new -nodes -key private/ca.key -sha256 -days 1095 \
    -out certs/ca.crt \
    -subj "/C=VN/ST=HN/O=Flasky-Lab/CN=Flasky-Lab-Root-CA"

# Dùng Root CA vừa tạo để ký ra 1 cert riêng cho chính LB, cert này mới thực sự được HAProxy dùng để phục vụ HTTPS:
cd /opt/ca

## Tạo private key riêng cho LB
sudo openssl genrsa -out private/lb.key 2048

## Tạo file .csr để xin Root CA cấp .crt
sudo openssl req -new -key private/lb.key -out certs/lb.csr \
  -subj "/C=VN/ST=HN/O=Flasky-Lab/CN=flasky.lab.local"

## Khai báo SAN để giúp trình duyệt nhận biết được IP của hệ thống máy chủ
sudo tee certs/lb.ext > /dev/null <<'EOF'
subjectAltName = DNS:flasky.lab.local, IP:10.0.10.10 
EOF

## Ký CSR bằng Root CA → tạo ra cert thật
sudo openssl x509 -req -in certs/lb.csr -CA certs/ca.crt -CAkey private/ca.key \
  -CAcreateserial -out certs/lb.crt -days 825 -sha256 -extfile certs/lb.ext

## Gộp cert + key thành 1 file .pem cho HAProxy
sudo cat certs/lb.crt private/lb.key | sudo tee certs/lb.pem > /dev/null
sudo chmod 644 /opt/ca/certs/lb.pem
```

**Note**: Tóm gọn toàn bộ chuỗi tin cậy (chain of trust)

```text
Root CA (tự ký, ca.key ký ca.crt)
    │
    └── ký CSR của LB (lb.csr) 
            │
            └── ra cert lb.crt (có chữ ký của CA)
                    │
                    └── gộp với lb.key → lb.pem → HAProxy dùng để serve HTTPS
```

Khi client kết nối <https://flasky.lab.local>, HAProxy gửi lb.crt (nằm trong lb.pem) cho client. Client kiểm tra chữ ký trên lb.crt có khớp với ca.crt mà nó tin tưởng (đã import) hay không — nếu khớp, kết nối được coi là an toàn.

Ngoài ra, việc tạo Root CA nội bộ trên LB thêm có lý do đó là:

- Chỉ cần import 1 lần file ca.crt vào máy client/trình duyệt (hoặc hệ thống) là mọi cert do CA này ký sau này đều tự động được tin tưởng — không cần import từng cert riêng lẻ mỗi khi bạn tạo thêm service HTTPS mới trong lab (ví dụ sau này thêm cert cho Grafana, MinIO console...)

- Mô phỏng đúng mô hình PKI thật của doanh nghiệp — nhiều công ty có CA nội bộ riêng để cấp cert cho hệ thống nội bộ, không cần cert công khai từ Let's Encrypt

```bash
import uuid
from flask import current_app
from minio import Minio


def get_minio_client():
    return Minio(
        current_app.config['MINIO_ENDPOINT'],
        access_key=current_app.config['MINIO_ACCESS_KEY'],
        secret_key=current_app.config['MINIO_SECRET_KEY'],
        secure=current_app.config['MINIO_SECURE'],
        region='us-east-1'
    )


def upload_avatar(file_storage, user_id):
    client = get_minio_client()
    bucket = current_app.config['MINIO_BUCKET']

    ext = file_storage.filename.rsplit('.', 1)[-1].lower()
    object_name = 'avatars/{}/{}.{}'.format(user_id, uuid.uuid4().hex, ext)

    file_storage.stream.seek(0, 2)
    size = file_storage.stream.tell()
    file_storage.stream.seek(0)

    client.put_object(bucket, object_name, file_storage.stream, size,
                       content_type=file_storage.mimetype)

    scheme = 'https' if current_app.config['MINIO_SECURE'] else 'http'
    return 'https://flasky.lab.local/{}/{}'.format(bucket, object_name)
```

### `Bước 7`: Hướng dẫn chạy các service theo trình tự để hệ thống hoạt động trơn tru

```text
DB node:
  mkdir + tạo hết file (.env-*, redis.conf, sql init...)
  chown/chmod .env
  docker compose up -d
  → tạo MinIO bucket + access key + policy (mc)
  → tạo backup_user trong MariaDB

Monitor node:
  mkdir + tạo config (prometheus.yml, loki-config.yml, datasource.yml)
  chown UID cho grafana/data, loki/data, prometheus/data
  docker compose up -d

Web1 + Web2:
  mkdir + Dockerfile + boot.sh (chmod +x)
  .env điền secret key MinIO thật (lấy từ bước DB)
  chmod 600 .env
  docker compose build && docker compose up -d
  → xử lý alembic_version, chạy migration avatar_url

LB:
  mkdir + tạo Root CA, ký cert lb.pem
  haproxy.cfg, blackbox.yml, promtail-config.yml
  docker compose up -d
```
